# 多机部署：Git 管代码，Docker 管环境

> 答你最初的问题："用 Git 来管理项目，是不是只能管理项目自身的内容？"  
> **是的，但这就够了。剩下的由 Docker 来管。**

---

## 先明确分工

```
┌─────────────────────────────────────────────────────┐
│                    GitHub 仓库                        │
│                                                     │
│  ├── 代码（*.py）      ← Git 管                     │
│  ├── 文档（*.md）      ← Git 管                     │
│  ├── 配置（*.yaml）    ← Git 管                     │
│  ├── 脚本（*.sh）      ← Git 管                     │
│  └── Dockerfile        ← Git 管（环境配方，纯文本）    │
│                                                     │
│  ❌ 不在 GitHub 上：                                  │
│  ├── Isaac Sim 镜像 (23GB)  → NVIDIA NGC             │
│  ├── GPU 驱动               → NVIDIA 官网             │
│  ├── 训练日志 + Checkpoint  → 本地 / 云存储           │
│  └── sim/ 下的 3 个仓库     → 各自在 GitHub 上独立管理  │
└─────────────────────────────────────────────────────┘
```

## 场景 1：两台电脑，同一个项目

你在实验室台式机训练，回家想用自己的笔记本继续调参数。

```bash
# ===== 在实验室台式机上 =====
# 1. 训好了，把代码改动 push 到 GitHub
git add .
git commit -m "调整奖励权重，训练效果提升"
git push

# 2. 把最新的 checkpoint 手动传到笔记本
# （日志和模型不上 Git，用 U 盘/scp/云盘）
scp -r logs/rsl_rl/unitree_g1_29dof_velocity/2026-06-24_* \
    你的笔记本:~/projects/g1-rl/logs/rsl_rl/unitree_g1_29dof_velocity/


# ===== 回到家的笔记本上 =====
# 1. 拉取最新代码
git pull

# 2. 确认 Docker 环境一样（相同 Dockerfile 构建的镜像）
docker compose -f docker/docker-compose.yml up

# 3. 继续训练（环境一致，checkpoint 一致，结果可比）
```

## 场景 2：4 人团队，一人一台不同配置的电脑

| 队员 | 电脑配置 | 怎么保证一致 |
|------|----------|-------------|
| 小明 | Ubuntu 22.04 + RTX 4060 | Docker 容器内统一 Ubuntu 24.04 |
| 小红 | Ubuntu 24.04 + RTX 4080 | Docker 容器内统一 Ubuntu 24.04 |
| 小刚 | Ubuntu 26.04 + RTX 3080 Ti | Docker 容器内统一 Ubuntu 24.04 |
| 小美 | Windows 11 + RTX 4070 | Docker 容器内统一 Ubuntu 24.04 + WSL2 |

**四个人进入 Docker 容器后，环境完全一致。** GPU 型号不同不影响训练结果（只影响训练速度）。

团队协作流程：

```bash
# 每人初始：
git clone git@github.com:GXMZU-AITECC/unitree-g1-demo.git
cd unitree-g1
git checkout -b xiaoming/experiment1    # 各自开分支
docker compose up                         # 统一环境

# 调参时：
# 改代码 → 跑训练 → 记录结果
# 改动只推送到自己的分支
git push origin xiaoming/experiment1

# 定期同步：
git checkout main
git pull origin main                     # 拉别人的文档/脚本更新
git checkout xiaoming/experiment1
git merge main                           # 合并到自己的实验分支
```

## 场景 3：提交到机器人比赛

这是"标准化"的最高层级——评委需要能在**一台没有参赛者任何环境的空机器上**跑你的训练。

```
评委的机器（刚装好 Ubuntu + Docker）
    │
    │ docker pull <你的镜像>
    │ docker run <你的镜像>
    │
    ▼
┌─────────────────────────┐
│ 你的 Docker 镜像          │
│ ├─ 完整的 Isaac Sim      │
│ ├─ 你的训练代码           │
│ ├─ 你的模型 checkpoint   │
│ └─ 你的启动脚本           │
│                          │
│ 评委不需要装任何东西       │
│ 跑出来的结果和你完全一样   │
└─────────────────────────┘
```

具体操作看 [4.5_竞赛部署：自建镜像](4.5_competition_submit.md)。

## 为什么 Git 不能再管理更多？

### Git 的设计哲学

Git 是 Linus Torvalds 为 Linux 内核开发的——内核的代码全是纯文本。Git 的核心能力是**逐行追踪文本变化**：谁在什么时候改了哪一行。

```
Git 擅长：                           Git 不擅长：
✅ 代码是谁写的、什么时候写的           ❌ 这个镜像里 CUDA 版本是多少
✅ 这一行是谁删的、为什么删             ❌ GPU 驱动版本对不对
✅ 合并两个人的修改                    ❌ Python 3.10 和 3.12 装哪个
✅ 回退到 3 天前的代码版本             ❌ 操作系统是 Ubuntu 还是 CentOS
```

### 那配置这些环境的东西真的不能管吗？

能管——但不是"管环境本身"，而是"管环境的配方"：

| 管什么 | 用什么文件 | 这个文件能被 Git 管吗？ |
|--------|-----------|------------------------|
| Python 依赖 | `requirements.txt` / `pyproject.toml` | ✅ 纯文本，Git 完美管理 |
| Conda 环境 | `environment.yml` | ✅ 纯文本 |
| Docker 构建 | `Dockerfile` | ✅ 纯文本 |
| Docker 服务编排 | `docker-compose.yml` | ✅ 纯文本 |
| VS Code 配置 | `.devcontainer/*.json` | ✅ 纯文本 |
| Isaac Sim 镜像 (23GB) | — | ❌ 在 NVIDIA NGC 上，不在 GitHub |
| GPU 驱动 | — | ❌ 在 NVIDIA 官网，每台机器自己装 |
| 训练 checkpoint | — | ❌ 太大（几十 MB 一个），且频繁变化 |

**你只需要管好配方文件，让学生/评委照着配方重建就行。**

## 总结

```
你的问题                        → 答案

Git 只能管代码吗？              → 不是。Git 还能管一切纯文本文件：文档、配置、环境配方（Dockerfile）
Docker 环境能同步到 GitHub 吗？  → 不能。23GB 的镜像存在 Docker Hub/NGC，不在 GitHub
那怎么标准化？                  → GitHub 上放配方（Dockerfile），团队/评委自行构建相同的环境
机器人比赛怎么做？              → 三层：本地开发(Docker+脚本) → 团队协作(dev container) → 比赛提交(Docker镜像)
```
