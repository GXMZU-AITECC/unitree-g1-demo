# 竞赛部署 — 构建自己的训练 Docker 镜像

> 这章是给要做比赛、需要让别人能**逐位相同地复现**你的训练结果的人看的。
>
> 如果你只是在本地训练，跳过这章，用 `bash scripts/start.sh train` 就行。

---

## 什么时候需要自己构建 Docker 镜像？

1. **比赛提交**：评委需要在你提交的镜像里直接跑你的训练/推理代码，环境必须一致
2. **团队协作**：4 个队员的电脑各不相同，要保证所有人训练出来的结果可比
3. **云端训练**：想在 AWS / 阿里云 GPU 实例上跑训练，需要一个自包含的镜像

## 第 1 步：理解 Dockerfile 的结构

一个 Dockerfile 就像是"从零开始配一台电脑"的清单：

```dockerfile
# 第 1 行：声明基础镜像（用什么"操作系统"）
FROM nvcr.io/nvidia/isaac-sim:5.1.0

# 第 2-N 行：安装额外的东西
RUN /isaac-sim/kit/python/bin/python3 -m pip install gymnasium rsl-rl-lib==5.0.1

# 最后一行：容器启动时执行什么
CMD ["bash", "/workspace/scripts/start.sh", "train"]
```

### Dockerfile 指令白话对照表

| 指令 | 白话 |
|------|------|
| `FROM` | "从一个现成的厨房开始"就是 NGC 提供的 Isaac Sim 镜像 |
| `RUN` | "在厨房里装点东西"装 Python 包、系统工具等等 |
| `COPY` | "把你的菜谱贴到厨房墙上"把本地的代码/配置复制进镜像 |
| `WORKDIR` | "在厨房的哪个位置工作"设默认工作目录 |
| `CMD` | "厨师进厨房后第一件事做什么"容器启动时默认执行的命令 |

## 第 2 步：项目自带的 Dockerfile

我们已经在 `docker/Dockerfile` 为你准备好了最小化的训练镜像。

文件在：[`docker/Dockerfile`](../docker/Dockerfile)

你可以直接用：

```bash
cd ~/projects/g1-rl

# 构建镜像
sudo docker build -f docker/Dockerfile -t g1-rl-train:latest .

# 用构建好的镜像跑训练
sudo docker run --rm --gpus all --user 0:0 \
  -e ACCEPT_EULA=Y -e OMNI_KIT_ALLOW_ROOT=1 \
  --network=host \
  -v ~/projects/g1-rl/logs:/isaac-sim/logs \
  g1-rl-train:latest
```

## 第 3 步：一键启动（docker compose）

比手写 `docker run` 更方便的是用 `docker compose`：

```bash
cd ~/projects/g1-rl

# 一键启动（自动构建镜像 + 运行容器）
docker compose -f docker/docker-compose.yml up

# 如果改过 Dockerfile，强制重建：
docker compose -f docker/docker-compose.yml up --build
```

`docker-compose.yml` 的内容解读：

```yaml
services:
  g1-train:
    build:
      context: ..              # 从项目根目录构建
      dockerfile: docker/Dockerfile
    runtime: nvidia            # 用 NVIDIA GPU
    environment:
      - ACCEPT_EULA=Y          # 接受 Isaac Sim 用户协议
      - OMNI_KIT_ALLOW_ROOT=1  # 允许 root 用户运行
    volumes:
      - ../logs:/isaac-sim/logs    # 训练日志持久化到宿主机
      - ../sim:/sim:ro            # G1 代码仓库（只读）
    network_mode: host            # 用宿主机网络（少一层 NAT）
```

## 第 4 步：推送到 Docker Hub（比赛提交）

```bash
# 1. 登录 Docker Hub（需要注册账号：https://hub.docker.com/）
sudo docker login

# 2. 给镜像打标签
sudo docker tag g1-rl-train:latest <你的用户名>/g1-rl-train:v1.0

# 3. 推送
sudo docker push <你的用户名>/g1-rl-train:v1.0
```

推送后，评委（或队友）只需：

```bash
sudo docker pull <你的用户名>/g1-rl-train:v1.0
sudo docker run --rm --gpus all <你的用户名>/g1-rl-train:v1.0
```

环境和你的完全一样。

## 第 5 步：镜像瘦身（进阶）

Isaac Sim 基础镜像 23GB，加上你的代码和依赖可能到 25GB+。几个瘦身技巧：

1. **多阶段构建**：构建阶段用完整镜像，最终镜像只保留需要的文件
2. **`.dockerignore`**：排除 `logs/`、`models/`、`__pycache__/` 等不需要的目录
3. **合并 RUN 层**：多个 `RUN` 命令合并成一个，减少镜像层数

```dockerfile
# 好的写法（合并 RUN）
RUN apt-get update && apt-get install -y curl && \
    pip install gymnasium && \
    rm -rf /var/lib/apt/lists/*   # 清理 apt 缓存

# 不好的写法（每个 RUN 产生一层）
RUN apt-get update
RUN apt-get install -y curl
RUN pip install gymnasium
```

## 常见问题

### Q: 为什么不用 GitHub Actions 自动构建镜像？
A: Isaac Sim 镜像 23GB，GitHub Actions 的免费额度不够。本地构建 + Docker Hub 手动推送是最省事的方式。

### Q: 我可以把训练好的模型也打进镜像里吗？
A: 不建议。模型文件（`.pt`）会频繁更新，而且一个模型 10MB+。正确的做法是：镜像里不放模型，用 volume 挂载 `models/` 目录到容器里；或者单独上传模型到 HuggingFace / Google Drive。

### Q: 队友的镜像能在我电脑上跑吗？
A: 只要你的电脑有 NVIDIA GPU + Docker + NVIDIA Container Toolkit，就可以。这就是 Docker 的核心价值——**环境可移植**。
