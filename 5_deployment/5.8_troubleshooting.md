# 5.8 部署排错速查

> 机器人不动？报错了？查这张表。

---

## 启动阶段

### "Unmatched robot type"

**中文意思**：代码是给 29 关节机器人的，你的机器人可能不是 29 关节版本。

**怎么办**：检查你的 G1 型号。G1 有 23dof（无腰部）和 29dof（有腰部）两个版本。如果你的是 23dof，需要换对应的部署代码。

---

### "Waiting for connection to robot..." 然后一直等待

**中文意思**：程序找不到机器人的电机控制器。

**可能原因和解决办法**：

| 原因 | 怎么检查 | 怎么解决 |
|------|---------|---------|
| 网卡名字写错了 | `ifconfig` 看有哪些网卡 | 换成实际网卡名：`./g1_ctrl --network wlan0` |
| DDS 没在运行 | `ps aux \| grep dds` | 联系管理员重启 DDS 服务 |
| 机器人没开机 | —— | 确认机器人控制器已经启动 |

试试不同的网络接口：
```bash
./g1_ctrl --network eth0
./g1_ctrl --network enp3s0
./g1_ctrl --network wlan0
```

---

### "The other process is using the lowcmd channel"

**中文意思**：已经有一个控制器程序在跑了，占住了通道。

**怎么办**：
```bash
# 找到并杀掉旧的进程
ps aux | grep g1_ctrl
kill <PID>
# 然后重新运行
./g1_ctrl --network eth0
```

## 编译阶段

### "cmake: command not found"

```bash
sudo apt install cmake -y
```

### "g++: command not found"

```bash
sudo apt install build-essential -y
```

### "fatal error: unitree/robot/..."

**中文意思**：机器人上没有装 `unitree_sdk2`。

**怎么办**：宇树的 SDK 通常出厂已装好。如果没装，联系机器人供应商或实验室管理员。这个 SDK 不在公开网络上，需要从宇树获取。

### 找不到 ONNX Runtime（头文件或 `.so`）

两种表现，根子都是同一个：cmake 找的那个 `ONNXRUNTIME_ROOT` 底下没有 ONNX Runtime。

```
CMake Error: 找不到 ONNX Runtime 头文件: .../include/onnxruntime_cxx_api.h
```

以前这里更坑：cmake 一声不响地配置成功，到 `make` 才吐

```
fatal error: onnxruntime_cxx_api.h: No such file or directory
undefined reference to `Ort::Env::Env(...)'
```

现在 cmake 阶段就直接把原因和两条命令打给你了。按它说的做，两条路：

```bash
# 1) 压根没装过
cd ~/g1-rl-deploy && bash install_onnxruntime.sh

# 2) 装过，但换了一个 SSH 会话，环境变量丢了（最常见的翻车姿势）
export ONNXRUNTIME_ROOT=~/g1-rl-deploy/thirdparty/onnxruntime-linux-x64-1.22.0
cd ~/g1-rl-deploy/g1_29dof/build
rm -f CMakeCache.txt && cmake .. -DCMAKE_BUILD_TYPE=Release && make -j
```

> 想让它以后不再丢：把那行 `export` 追加到机器人上的 `~/.bashrc` 末尾（见 5.6 第一步）。
> 报的是"运行库找不到"而不是"头文件找不到" → 解压不完整或架构不对（本仓装的是 `linux-x64`）。

### 无法联网下载 ONNX Runtime

如果机器人不能上外网，在能上网的机器上先下载好：

```bash
# 在能上网的机器上
wget https://github.com/microsoft/onnxruntime/releases/download/v1.22.0/onnxruntime-linux-x64-1.22.0.tgz
tar xzf onnxruntime-linux-x64-1.22.0.tgz

# 用 U 盘或 scp 把解压后的整个文件夹传到机器人的
# ~/g1-rl-deploy/thirdparty/onnxruntime-linux-x64-1.22.0/
```

最后在机器人上设置路径：
```bash
export ONNXRUNTIME_ROOT=~/g1-rl-deploy/thirdparty/onnxruntime-linux-x64-1.22.0
```

## 运动阶段

### 机器人站不稳，一直抖

**可能原因**：PD 刚度参数和真机不完全匹配。

**怎么办**：仿真里的刚度和真实电机不完全一样是正常的。如果抖动不严重，让机器人走几步可能就稳了。如果抖得厉害：
1. 先按 L2+B 回到 Passive
2. 在 `params/deploy.yaml` 中微调 stiffness（减小 10-20%）
3. 重新运行

### 机器人走几步就自动切回 Passive

**中文意思**：`bad_orientation` 保护机制触发了——机器人倾斜角超过了安全阈值（约 57°）。

这是**好事**——说明保护机制在工作。但也说明：
- 模型可能训练不够（18100 步的模型确实还没完全收敛）
- 真机物理和仿真不一样

**怎么办**：换个更早期的 checkpoint 试试（比如 model_10000），或者继续训练更多步再部署。

### 机器人原地不动，或者在原地小幅抖动

**中文意思**：ONNX 模型推理正常，但输出的动作太小。

这**不是 bug**。模型输出范围是 [-1,1]，乘以 scale=0.25 就是 ±14° 的关节偏移，本来就应该是 "小步慢走"。

如果**完全不动**（不是小步走，是一点都不动）：
1. 检查摇杆输入方向——推左摇杆 ↑
2. 确认模型文件路径正确（启动时日志里的 `Policy directory:` 那行）

### 机器人向后倒

后退和快速转向对模型来说比较难。先练习慢速前进，稳定了再试其他方向。

---

## 向管理员求助时，请带这些信息

如果你解决不了，去问实验室师兄/管理员时，最好带上：

1. 机器人的型号（G1 23dof / 29dof）
2. `uname -a` 的输出（操作系统版本）
3. 编译和运行的**完整终端输出**（截图或复制粘贴）
4. 你用的哪个 ONNX 模型（训练时间戳）
5. 现象的具体描述（站起来了？走了几步？往哪个方向倒？）
