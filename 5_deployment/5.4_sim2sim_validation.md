# 5.4 Sim2Sim：上真机之前，先在 MuJoCo 里验证

> 这是宇树官方部署流程里**最关键的一步**。
>
> 模型在 Isaac Sim 里走得再好，也不代表在真机上能走。但如果在 MuJoCo 里也能走，那成功率就高很多了。
>
> **永远先跑 Sim2Sim，确认模型在 MuJoCo 里不摔，再上真机。**

---

## 类比：上路之前先练模拟器

```
驾校场地练车        →  考驾照       →  上路
    ↑                     ↑              ↑
Isaac Sim 训练      MuJoCo 验证    G1 真机行走
（GPU 超级加速）     （另一个物理引擎） （现实世界）
```

MuJoCo 是 Google DeepMind 开源的物理仿真引擎。和 Isaac Sim 的 PhysX 引擎不一样，所以如果模型在两个不同的物理引擎里都能走路，说明它学到的策略是**真的会走路**，而不只是在某个仿真器里 "作弊"。

---

## 前提：安装 unitree_mujoco

### 1. Clone 代码

```bash
cd ~/projects/g1-rl/sim
git clone git@github.com:unitreerobotics/unitree_mujoco.git
```

### 2. 安装依赖

```bash
# 系统库
sudo apt install -y libyaml-cpp-dev libboost-all-dev libeigen3-dev libspdlog-dev libfmt-dev

# ONNX Runtime（如果还没装的话——部署的时候已经装过了）
# 在 deploy/thirdparty/ 下
cd ~/projects/g1-rl
bash deploy/install_onnxruntime.sh
```

### 3. 编译 unitree_mujoco

需要 MuJoCo 本体（MuJoCo 3.x）：

```bash
# 先下载 MuJoCo
# 如果还没装过：
wget https://github.com/google-deepmind/mujoco/releases/download/3.3.0/mujoco-3.3.0-linux-x86_64.tar.gz
# 不用解压到系统目录，unitree_mujoco 的 CMake 会用 find_package 找

# 编译 MuJoCo 仿真界面
cd ~/projects/g1-rl/sim/unitree_mujoco/simulate
mkdir -p build && cd build
cmake .. && make -j$(nproc)
```

> 如果 cmake 找不到 mujoco，设一下环境变量：`export MUJOCO_ROOT=/path/to/mujoco-3.3.0`

### 4. 配置 MuJoCo

编辑 `sim/unitree_mujoco/simulate/config.yaml`：

```yaml
robot: g1                    # 机器人型号
domain_id: 0                 # DDS domain id（0 = 只在本机通信）
enable_elastic_hand: 1       # 开启弹性手
use_joystick: 1              # 用手柄
```

> 这里 `domain_id: 0` 的 DDS 通信只在本机 localhost 上跑，不和外界交互。所以不需要 `--network` 参数。

## 验证流程：从编译到走路

### 第一步：启动 MuJoCo 仿真窗口

```bash
cd ~/projects/g1-rl/sim/unitree_mujoco/simulate/build

# 设置 ONNX Runtime 路径
export ONNXRUNTIME_ROOT=~/projects/g1-rl/deploy/thirdparty/onnxruntime-linux-x64-1.22.0

# 启动
./unitree_mujoco
```

你会看到一个弹出来的窗口，里面有一个平躺在地上的 G1 机器人——这就是 MuJoCo 的渲染画面。

### 第二步：编译 g1_ctrl（如果还没编译）

```bash
cd ~/projects/g1-rl/deploy/g1_29dof
mkdir -p build && cd build

export ONNXRUNTIME_ROOT=~/projects/g1-rl/deploy/thirdparty/onnxruntime-linux-x64-1.22.0
cmake .. && make -j$(nproc)
```

### 第三步：跑 RL 策略

在另一个终端里：

```bash
cd ~/projects/g1-rl/deploy/g1_29dof/build
./g1_ctrl
```

> ⚠️ 注意：Sim2Sim 不需要 `--network eth0`！MuJoCo 里的控制器和仿真在**同一台机器**上通过 DDS localhost 通信（domain_id=0），不需要指定网卡。

### 第四步：按手柄操作

启动后，终端会提示：

```
Press [L2 + Up] to enter FixStand mode.
And then press [R1 + X] to start controlling the robot.
```

按照官方的操作序列：

| 步骤 | 操作 | 发生了什么 |
|------|------|----------|
| 1 | **L2 + ↑** | 机器人站起来（FixStand） |
| 2 | 鼠标点击 MuJoCo 窗口，按键盘 **8** | 机器人脚落地（关闭弹性悬挂） |
| 3 | **R1 + X** | 策略开始运行，机器人走路！ |
| 4 | 鼠标点击 MuJoCo 窗口，按键盘 **9** | 关闭弹性带（elestic band） |

### 第五步：观察

在 MuJoCo 窗口里观察：
- 机器人**站得稳不稳**？有没有一直抖？
- 机器人**能按摇杆方向走吗**？（前进、后退、左右转）
- 机器人**会不会走着走着摔倒**？

如果你在 MuJoCo 里看到机器人能平稳走路 30 秒以上，不摔不倒——

**可以上真机了！** → [5.5 部署代码准备](5.5_deploy_code_setup.md)

## 如果 MuJoCo 里也摔了？

说明模型训练还不够。回到 Isaac Sim 继续训练：

```bash
# 回训练
bash scripts/start.sh resume

# 或者从头训练
bash scripts/start.sh train
```

训练更多步数，直到在 Isaac Sim 里走稳了（bad_orientation ~0, mean_reward ~5+），再重新导出 ONNX，再做一次 Sim2Sim 验证。

## 常见问题

### "./unitree_mujoco: error while loading shared libraries: libmujoco.so"

MuJoCo 的动态库没在系统路径里。

```bash
# 找到 libmujoco.so 的位置
find ~ -name "libmujoco*.so*" 2>/dev/null

# 加到 LD_LIBRARY_PATH
export LD_LIBRARY_PATH=/path/to/mujoco/lib:$LD_LIBRARY_PATH
./unitree_mujoco
```

### "DDS 报错" 或 "channel timeout"

确认 `config.yaml` 里 `domain_id` 设为 0。domain_id=0 表示只在本机回环（localhost）通信。

### cmake 找不到 mujoco

```bash
# 下载 MuJoCo 3.3.0
wget https://github.com/google-deepmind/mujoco/releases/download/3.3.0/mujoco-3.3.0-linux-x86_64.tar.gz
tar xzf mujoco-3.3.0-linux-x86_64.tar.gz -C ~/

# 告诉 cmake 去哪找
export MUJOCO_ROOT=~/mujoco-3.3.0
cd sim/unitree_mujoco/simulate/build
cmake ..
```

### 编译 g1_ctrl 时报 ONNX Runtime 错误

确认你跑了 `bash deploy/install_onnxruntime.sh` 并且设置了 `ONNXRUNTIME_ROOT`：

```bash
export ONNXRUNTIME_ROOT=~/projects/g1-rl/deploy/thirdparty/onnxruntime-linux-x64-1.22.0
```
