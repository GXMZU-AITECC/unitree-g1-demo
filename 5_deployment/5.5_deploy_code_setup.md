# 5.5 部署代码准备

> 你已经验证了模型在 MuJoCo 里能走。现在把 C++ 部署代码准备好，然后推到机器人上。

---

## deploy/ 里面有什么？

我们在项目根目录下有一个 `deploy/` 文件夹，里面是从 unitree_rl_lab 复制过来的 C++ 代码，专门为 G1 29-DOF 速度跟踪任务准备的：

```
deploy/
├── include/                    共享 C++ 头文件
│   ├── FSM/                   有限状态机框架（Passive → FixStand → Velocity）
│   ├── isaaclab/              Isaac Lab 的 C++ 版本（环境、观测、动作）
│   ├── param.h                配置加载 + 策略目录自动发现
│   ├── unitree_articulation.h 机器人硬件抽象层（读 IMU/电机 → 观测向量）
│   └── unitree_joystick_dsl.hpp
├── g1_29dof/
│   ├── main.cpp               程序入口
│   ├── CMakeLists.txt         构建配置
│   ├── src/
│   │   ├── State_RLBase.cpp   RL 速度跟踪控制器
│   │   └── State_Mimic.cpp    动作模仿控制器
│   └── config/
│       ├── config.yaml         FSM 配置（手柄按键、策略路径）
│       └── policy/velocity/v0/ ← 你的 ONNX 模型放这里
├── thirdparty/                 ONNX Runtime（通过脚本下载到这个位置）
├── install_onnxruntime.sh     一键安装 ONNX Runtime
└── .gitignore                 排除不应该提交到 git 的文件
```

---

## 把模型放到 deploy 里

如果你的 exported/ 还没内容——先导出：

```bash
# 方法一：自动导出（推荐）
bash scripts/deploy.sh export

# 方法二：先手动回放导出 ONNX，再复制
bash scripts/start.sh play 2026-06-24_09-29-56 model_18100.pt
bash scripts/deploy.sh export
```

确认模型就位：

```bash
ls -lh deploy/g1_29dof/config/policy/velocity/v0/exported/
# policy.onnx  约 1.7MB

ls -lh deploy/g1_29dof/config/policy/velocity/v0/params/
# deploy.yaml
```

## 构建你的 deploy 项目

构建时，`g1_ctrl` 会使用 ONNX Runtime 去加载你的 `policy.onnx`，自动发现策略路径（通过 `param.h` 中的 `parser_policy_dir` 逻辑）。

**架构理解**：你刚刚在 MuJoCo 验证时已经编译过 `g1_ctrl` 了。同一个二进制，同一个 ONNX 模型，既可以对接 MuJoCo 仿真（本机 localhost DDS），也可以对接真机（指定 `--network eth0` 连接真实 DDS 通道）。这就是 `unitree_rl_lab` 设计的巧妙之处——**Sim2Sim 和 Sim2Real 用完全相同的代码**。

---

## 推送到机器人

在机器人上编译还是在本地交叉编译都可以。这里按最简单的方式——把源码推到机器人上原地编译：

```bash
bash scripts/deploy.sh push 192.168.123.161
```

这个命令用 rsync 把 `deploy/` 目录传到机器人的 `~/g1-rl-deploy/` 下。ONNX Runtime 的 20MB 文件不会推（已被 .gitignore 排除），需要在机器人上单独安装。
