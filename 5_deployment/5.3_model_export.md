# 5.3 导出 ONNX 模型

> 你已经训练出了一个 `model_N.pt` 文件。它是一个 PyTorch 网络，只能在 Python 里跑。
>
> 机器人的电脑上没有 PyTorch，没有 GPU。它需要 **ONNX 格式** 的模型文件。
>
> 这章就是把 `.pt` 转成 `.onnx`，然后放到 `deploy/` 里准备发送。

---

## 类比：把 Word 文档导出成 PDF

```
你用 Word 写了一个文档    ←→  你用 PyTorch 训练了一个模型 (.pt)
你导出一份 PDF            ←→  你导出一个 ONNX 模型 (.onnx)
别人用免费的 PDF 阅读器看  ←→  机器人的 C++ 程序用 ONNX Runtime 读
```

ONNX 是一个**通用格式**。不管模型用什么框架训练的（PyTorch、TensorFlow……），导出成 ONNX 后都可以用同一个推理引擎跑。

---

## 你的模型在哪？

每次训练完成后，系统会自动导出 ONNX。去这里找：

```bash
ls ~/projects/g1-rl/logs/rsl_rl/unitree_g1_29dof_velocity/
```

你会看到类似这样的目录：

```
2026-06-24_09-29-56/        ← 这是你某次训练的"时间戳目录"
2026-06-25_14-30-00/        ← 另一次训练
```

进去看看：

```bash
ls ~/projects/g1-rl/logs/rsl_rl/unitree_g1_29dof_velocity/2026-06-24_09-29-56/
# 你会看到一大堆 model_100.pt, model_200.pt, model_300.pt ...
# 还有一个 exported/ 文件夹

ls ~/projects/g1-rl/logs/rsl_rl/unitree_g1_29dof_velocity/2026-06-24_09-29-56/exported/
# policy.onnx     ← 这就是机器人要用的！
# policy.pt       ← JIT 导出的 PyTorch 版本（备用）
```

---

## 方法一：用 deploy.sh 自动导出（推荐）

最简单的办法，一个命令搞定：

```bash
bash scripts/deploy.sh export
```

这个脚本会做什么：
1. 把 `logs/` 下所有训练记录列出来，让你选
2. 再让你选一个 checkpoint（检查点）
3. 把对应的 `policy.onnx` 和 `deploy.yaml` 复制到 `deploy/g1_29dof/config/policy/velocity/v0/`

**如果你已经有明确的目标**，也可以跳过交互，直接指定：

```bash
bash scripts/deploy.sh export 2026-06-24_09-29-56 model_18100
```

运行完你会看到：
```
✓ 导出完成！
  ONNX 模型: deploy/g1_29dof/config/policy/velocity/v0/exported/policy.onnx
  部署配置:  deploy/g1_29dof/config/policy/velocity/v0/params/deploy.yaml
```

---

## 方法二：如果 ONNX 还没导出（训练崩了没来得及）

如果你的训练中途崩了，`exported/` 目录是空的，需要手动触发导出：

```bash
# 回放一次模型——回放过程会自动导出 ONNX
bash scripts/start.sh play 2026-06-24_09-29-56 model_18100.pt
```

回放完成后再运行 `bash scripts/deploy.sh export` 就行了。

## 验证一下

确认文件已经复制好了：

```bash
ls -lh deploy/g1_29dof/config/policy/velocity/v0/exported/
# 应该有 policy.onnx，约 1.7 MB

ls -lh deploy/g1_29dof/config/policy/velocity/v0/params/
# 应该有 deploy.yaml
```

## deploy.yaml 是什么？

这个文件是训练自动生成的，**描述了 ONNX 模型的 "说明书"**：

- 输入是哪些数据（角速度、重力方向、关节角度、摇杆指令……）
- 输出是什么（29 个关节的目标角度偏移量）
- 各关节的刚度/阻尼怎么设
- 各数据的缩放因子是多少

**你不需要理解它每一行在说什么。** 把它和 `policy.onnx` 一起放着就行。C++ 程序会自动读它。

如果你好奇，可以 `cat deploy/g1_29dof/config/policy/velocity/v0/params/deploy.yaml` 看一眼——里面那个 `joint_ids_map` 是仿真关节编号和真实电机编号的对照表，`stiffness` 和 `damping` 是每个关节的 "软硬程度"。

> ⚠️ **不要手动改 deploy.yaml 里的任何数字。** 这些数字必须在仿真和真机之间保持完全一致。
