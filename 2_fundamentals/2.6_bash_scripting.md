# Bash 脚本怎么读 — 看懂 start.sh

> 你天天跑 `bash scripts/start.sh`。这个 `.sh` 文件是什么？里面的 `$`、`${}`、`if` 是什么意思？
>
> 这章以 `start.sh` 的节选为例，逐行解释。读完你能看懂大多数 Shell 脚本。

---

## `.sh` 文件是什么？

**Shell 脚本 = 终端命令的合集。**

你在终端里敲的每一条命令，都可以写进 `.sh` 文件，一行一条。然后 `bash 文件名.sh` 一次性全部执行。

```bash
# 这两个是等价的：

# 方式 1：在终端里一行一行敲
mkdir -p ~/projects/g1-rl/logs
ls ~/projects/g1-rl/
echo "Done"

# 方式 2：写进 script.sh 然后一次性跑
bash script.sh
```

## `start.sh` 逐段解读

### 第 1 段：Shebang 和设置

```bash
#!/bin/bash
# =============================================================================
# G1 RL Training Launcher
# =============================================================================
set -euo pipefail
```

| 行 | 什么意思 |
|----|----------|
| `#!/bin/bash` | "用 bash 来解释这个文件"。必须是第一行。 |
| `#` 开头的行 | 注释。不影响执行，给人看的。 |
| `set -euo pipefail` | 安全模式——任何命令出错就立刻停止（不要"出了错还继续跑"） |

### 第 2 段：变量定义

```bash
TRAIN_TASK="${TRAIN_TASK:-Unitree-G1-29dof-Velocity}"
TRAIN_NUM_ENVS="${TRAIN_NUM_ENVS:-4}"
TRAIN_MAX_ITER="${TRAIN_MAX_ITER:-20000}"

IMAGE="nvcr.io/nvidia/isaac-sim:5.1.0"
SIM_DIR="${HOME}/projects/g1-rl/sim"
CACHE_DIR="${HOME}/.cache/isaac-sim"
LOG_DIR="${HOME}/projects/g1-rl/logs"
```

| 语法 | 什么意思 | 例子 |
|------|----------|------|
| `NAME=value` | 定义一个变量 | `IMAGE="nvcr.io/..."` |
| `${NAME}` | 读取变量的值 | `echo ${IMAGE}` 输出镜像名 |
| `${NAME:-default}` | 如果没设置，用默认值 | `TRAIN_NUM_ENVS="${TRAIN_NUM_ENVS:-4}"` |
| `${HOME}` | 自动变量：你的家目录 | `/home/lyh` |

### 第 3 段：创建目录

```bash
mkdir -p "${CACHE_DIR}"/{kit,ov,pip,glcache,computecache,logs,data,documents}
```

| 语法 | 什么意思 |
|------|----------|
| `mkdir -p` | 创建目录，`-p` = 父目录不存在时自动建 |
| `{kit,ov,pip,...}` | Brace expansion——等价于分别写 `kit/`、`ov/`、`pip/`…… |

这一行等于写了 8 条 `mkdir`。

### 第 4 段：Docker 启动命令

```bash
DOCKER_BASE="docker run --rm --gpus all --user 0:0 \
  -e ACCEPT_EULA=Y -e OMNI_KIT_ALLOW_ROOT=1 \
  --shm-size=8g --network=host \
  -v ${CACHE_DIR}/kit:/isaac-sim/kit/cache:rw \
  -v ${SIM_DIR}:/sim:rw \
  -v ${LOG_DIR}:/isaac-sim/logs:rw"
```

| 语法 | 什么意思 |
|------|----------|
| `\` | 续行符——这一行没写完，下一行接着 |
| `-e KEY=VALUE` | 设环境变量 |
| `-v HOST:CONTAINER:rw` | 挂载：宿主机目录 ↔ 容器目录，`rw` = 可读写 |

`DOCKER_BASE` 变量的值是整个 `docker run ...` 命令（多行拼接的）。

### 第 5 段：函数定义

```bash
train() {
    echo -e "${GREEN}=== G1 RL Training (headless) ===${NC}"
    echo "Task: ${TRAIN_TASK}  Envs: ${TRAIN_NUM_ENVS}  Iter: ${TRAIN_MAX_ITER}"
    run_python "/sim/unitree_rl_lab/scripts/rsl_rl/train.py --task ${TRAIN_TASK} --num_envs ${TRAIN_NUM_ENVS} --max_iterations ${TRAIN_MAX_ITER} --headless"
    echo -e "${GREEN}Done. Models: ${LOG_DIR}${NC}"
}
```

| 语法 | 什么意思 |
|------|----------|
| `train() { ... }` | 定义一个叫 `train` 的函数 |
| `echo -e` | 打印到终端，`-e` = 支持颜色代码（`${GREEN}`） |
| `run_python` | 另一个函数（在前面定义的，封装了 docker run 的复杂参数） |

### 第 6 段：主逻辑

```bash
case "${1:-menu}" in
    install|i)             install ;;
    train|t)               train ;;
    train-gui|tg)          train_gui ;;
    play|p)                play "${2:-}" "${3:-}" ;;
    shell|s|bash|sh)       shell ;;
    *)
        echo "Usage: bash scripts/start.sh [visualize|train|...]"
        exit 1 ;;
esac
```

| 语法 | 什么意思 |
|------|----------|
| `case` | 分支判断——根据用户输入，做不同的事 |
| `${1}` | 脚本的第一个参数。`bash start.sh train` → `${1}` = `train` |
| `${1:-menu}` | 没给参数时默认 `menu` |
| `install\|i)` | 匹配 `install` 或 `i` |
| `*)` | default 分支：都不匹配时走这 |
| `;;` | case 分支的结束标记 |

## 你现在能看懂 start.sh 的完整逻辑了

```
1. 定义变量（训练任务、环境数、镜像名、目录路径）
2. 创建缓存目录
3. 定义 docker run 命令模板
4. 定义各函数（install、train、play、shell……）
5. 读第一个参数，匹配到对应的函数 → 执行
```

## 常见 Shell 错误

| 错误 | 原因 |
|------|------|
| `command not found` | 拼写错误，或没装这个命令 |
| `Permission denied` | `.sh` 文件没有可执行权限：`chmod +x script.sh` |
| `No such file or directory` | 路径写错了，或目录不存在（加 `-p` 能解决） |
| `unbound variable` | 用了没定义的变量。`set -u` 的副作用——去掉或确保变量已定义 |
