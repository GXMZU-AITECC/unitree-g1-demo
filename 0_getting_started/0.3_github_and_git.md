# GitHub 和 Git — 不只是"存代码的网盘"

> 你已经会用终端了。但你不可能用 U 盘把代码拷给队友——你需要 GitHub 和 Git。
>
> 这章讲清楚三件事：
> 1. **GitHub** 是什么（和网盘有什么区别）
> 2. **Git** 基本操作（四条命令就够用）
> 3. **为什么 Docker 镜像不在 GitHub 上**（菜谱 vs 厨房）

## GitHub 是什么？

### 最直观的理解

你把 GitHub 当作"代码的百度网盘"——这是一个**80% 正确、20% 错误**的理解。

**对的部分**：
- 可以把代码上传到云端
- 别人可以从云端下载你的代码
- 有历史版本记录

**错的部分**：
- GitHub 不只是"存文件"。它存的是**谁在什么时候改了哪一行，改了什么内容，为什么要改**
- 两个人同时改了同一个文件，GitHub 能**合并**两个人的修改（网盘只能"谁的版本覆盖谁的"）
- 任何人都可以**提出修改建议**（Pull Request），原主决定接不接受

### 一个类比

网盘就像一个共享 Word 文档：谁最后保存，谁说了算。

```
A 和 B 同时改 README.md：

网盘做法：          GitHub 做法：
A 保存了            A 提交了改动："修复了第3行的错别字"
B 覆盖了 A 的改动    B 提交了改动："新增了第10行的安装步骤"
A 的改动丢了！      Git 自动合并两处改动 → 都在 ✅
```

GitHub + Git 能自动合并，因为它逐行追踪变化，不是整个文件覆盖。

## Git 基本操作 — 四条命令就够

### 概念速览

```
你的电脑（本地仓库）              GitHub（远程仓库）
┌─────────────────────┐          ┌─────────────────────┐
│  README.md          │  push   │  README.md          │
│  scripts/start.sh   │ ──────▶ │  scripts/start.sh   │
│  ...                │  上传   │  ...                │
│                     │  ◀────── │                     │
│                     │  pull   │                     │
│                     │  下载   │                     │
└─────────────────────┘          └─────────────────────┘
```

| 命令 | 干什么 | 方向 |
|------|--------|------|
| `git clone` | 把整个仓库从 GitHub **复制**到你电脑 | 远程 → 本地 |
| `git pull` | 把别人的最新改动**拉取**到你电脑 | 远程 → 本地 |
| `git add` + `git commit` | **记录**你的改动到本地 | 本地 |
| `git push` | 把你的改动**推送**到 GitHub | 本地 → 远程 |

### `git clone` — 复制仓库到本地

```bash
# 把 GitHub 上的项目复制到你的电脑
git clone git@github.com:GXMZU-AITECC/unitree-g1-demo.git ~/projects/g1-rl

# 之后你就可以在 ~/projects/g1-rl/ 里看到所有文件了
ls ~/projects/g1-rl/
```

**`git clone` 你只需要做一次**。之后每次打开项目，文件都在你电脑上了。

### `git pull` — 拉取别人的最新改动

```bash
cd ~/projects/g1-rl
git pull
# 如果团队有人更新了文档，这条命令会把更新拉到你电脑上
```

### `git add` + `git commit` — 记录你的改动

```bash
# 你改了 README.md，想记录下来
git add README.md                    # 告诉 Git："这个文件的改动我要记录"
git commit -m "更新了训练步骤说明"    # 写一句话，说明你改了什么
```

### `git push` — 推送到 GitHub

```bash
git push
# 把你本地记录的所有改动上传到 GitHub
```

## `.gitignore` — 哪些文件不上传

打开项目里的 `.gitignore` 文件：

```
sim/        ← sim/ 下的是独立仓库，不上传
logs/       ← 训练日志太大，不上传
models/     ← 模型文件太大，不上传
*.pt        ← PyTorch 模型文件，不上传
```

这些文件/目录留在你本地，**每个人自己生成**。这就是为什么 `git clone` 之后你看不到 `sim/` 和 `logs/`——它们不在 GitHub 上。

## 菜谱 vs 厨房（回答你最核心的困惑）

现在你理解了 Git——它管理文本文件。那 Docker 镜像（23GB 的 Isaac Sim）怎么办？

```
📝 菜谱 (Git 管)                    🍳 厨房 (Docker 管)
─────────────────                   ─────────────────
代码 (.py)                          操作系统 (Ubuntu)
文档 (.md)                          GPU 驱动
配置 (.yaml)                        Python 3.10
环境配方 (Dockerfile) ← 也是文本！    Isaac Sim 仿真引擎
全部在 GitHub 上                    在 Docker Hub / NGC 上
                                    （不在 GitHub，太大了）
```

**关键点**：`Dockerfile` 是文本文件，它**描述了怎么搭厨房**。Git 管这个描述文件。但"厨房本身"（23GB 的镜像）存在专门的镜像仓库里。

你 `git clone` 拿到的是菜谱。`docker compose up` 是照着菜谱搭厨房。

> 👉 关于 Docker 的详细解释，在配环境时会讲到：[1.2_Docker基础](../1_environment/1.2_docker_basics.md)

## 常见问题

### Q: `git clone` 报 Permission denied？
A: 可能还没配 SSH key。跳到 [1.5_Isaac_Sim](../1_environment/1.5_isaac_sim_setup.md) 看怎么配 GitHub SSH。

### Q: 我改了代码，怎么知道我改了哪些文件？
```bash
git status       # 列出所有改动过的文件
git diff         # 显示具体改了哪一行
```

### Q: `commit` 和 `push` 有什么区别？
- `commit`：改动记录在你的电脑上（本地）
- `push`：把记录同步到 GitHub（远程）
- 你可以 commit 很多次，最后一起 push

### Q: 为什么是四条命令而不是六条/十条？
你入门阶段只需要 `clone`、`pull`、`commit`、`push`。等团队协作用到 `branch`、`merge`、`PR` 的时候再学——在 [4.1_Git协作流程](../4_advanced/4.1_git_workflow.md) 里。
